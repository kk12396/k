# 测试与系统化调试 Skill

## 禁止做法

- 未复现就直接改代码。
- 只根据错误编号、截图标题或猜测判断根因。
- 用 try/catch 吞掉异常、删除校验、返回假成功或无限重试掩盖问题。
- 修复一个入口后不检查同类代码和其他端。
- 未实际运行测试就声称“已全面修复”。

## 调试流程

1. 建立最小复现：环境、版本、设备、账号状态、输入、文件大小、网络条件、步骤、预期和实际结果。
2. 收集证据：崩溃堆栈、服务端日志、安装日志、网络请求、数据库状态、线程/内存、文件权限和最近变更。
3. 缩小范围：按 UI、业务、网络、数据库、文件、线程、生命周期、兼容性和第三方依赖分层排查。
4. 定位根因：解释为何发生、为何只在特定环境发生、哪些代码路径受影响。
5. 设计修复：优先修根因；说明兼容策略、数据影响、迁移和回滚。
6. 回归验证：原复现、边界、异常、旧功能、其他设备、其他端和升级路径。

## 测试层级

- 单元测试：数据转换、校验、规则、状态机和冲突策略。
- 集成测试：数据库、文件、API、登录、迁移和第三方接口。
- UI/流程测试：导航、输入、权限、空/错/加载、返回、旋转和安全区。
- 构建测试：干净环境安装依赖、编译、打包和产物检查。
- 升级测试：旧版本数据升级、覆盖安装、迁移重复执行和失败恢复。
- 跨端联调：同账号、同数据、离线、冲突、重复请求、版本不一致和上传下载。

## 常见高风险场景

大文件上传、长列表、OCR/模型、音视频、后台任务、暂停/恢复、页面退出、进程被杀、网络切换、磁盘不足、权限拒绝、重复点击、重复回调、数据库部分迁移和 KSWEB 共享存储兼容。

## 测试报告

最终记录测试环境、执行命令、测试用例数、通过/失败、产物哈希或路径、未测试原因、已知限制和复现步骤。未通过项不得从报告中省略。
