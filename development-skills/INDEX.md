# 玄忆工作室开发 Skills 索引

本目录用于网站、Android App、Windows 客户端、插件、后台及双端/三端项目。执行开发任务时先读本索引，再按任务读取对应 Skill；不得只读索引后凭经验跳过专项规则。

## 开发前一次性确认

只询问用户尚未说明且会影响实现的项目，合并成一次提问，得到答案后不重复确认：

1. 包含网页时：`网页版使用旧版（PHP7.4 + MySQL5.6/5.7）还是新版（PHP8.2 + MySQL8.0）？`
2. 包含后台时：部署范围是本机、内网还是公网；后台采用 `/adminsc + admincs/123456`、经典 `/admin + admin/123456`，还是自定义路径与账号密码。
3. App 连接云端时：云端地址、是否使用 HTTPS、地址固定打包还是允许配置，以及认证方式。云端 URL 可以出现在 APK 中，但任何能授权敏感操作的 App Secret、管理员密码、数据库密码或长期万能令牌不得打包进 APK。
4. Android 发布时：是否只用默认发布安全、启用加强加固，或指定可信第三方加固；是否已有正式签名证书。默认发布安全始终启用。

`123456` 等弱初始密码只允许按用户要求用于本机、内网或测试。公网部署必须要求自定义强密码或生成随机密码，并启用首次登录强制改密；若用户仍坚持弱密码，先明确风险，不得静默公开部署。隐藏后台路径只能减少扫描噪声，不能替代登录限速、强密码、权限校验、CSRF 和审计日志。

## 最高优先级规则

1. 普通 Android 项目未要求 AIDE/AIDE-Plus 时，根据需求选择原生 Android、Flutter 或成熟方案，必须实际生成可安装 APK；默认不强制交付 Android 源码。
2. 明确要求 AIDE/AIDE-Plus 时，才要求 Android 源码可在 AIDE-Plus 直接编译，并实际交付 APK 与源码。
3. App+网页双端默认交付：可安装 APK + 可部署网页版源码。网页+Android+PC 三端默认交付：可安装 APK + Windows EXE + 可部署网页版源码。未要求 AIDE 时，不强制交付 Android 源码；未要求 PC 源码时，不强制交付 PC 源码。
4. 不得用网页快捷方式、仅打开网址的套壳或伪 EXE 冒充独立客户端；用户明确允许 WebView/套壳时除外。
5. 双端/三端开发前必须先建立共享功能矩阵、数据模型、API 契约、状态码、权限、同步与错误处理，之后各端只能依据共享契约实现。
6. 设备端能完成的计算、转换、识别、生成、缓存和数据管理优先本地处理；仅同步、协作、备份和必要运营数据上云。
7. 用户明确要求“加固 APK”时直接执行可用的发布加固、构建、签名和安装验证，不得只给方案。第三方壳加固必须实际有可信工具且兼容项目；无法执行时明确区分“已完成内置加固”和“未执行第三方壳”，不得把 R8 混淆冒充完整壳加固。
8. 未实际构建、安装、部署、加固或测试的内容，必须标记未验证，不得宣称已完成。

## 推荐执行顺序

一次性环境与安全确认 → 读取专项 Skill → 功能矩阵/设计系统/API 契约 → 实现 → 单端测试 → 跨端联调 → 安全检查 → 迁移与升级验证 → 发布加固与构建安装包 → 最终验收与交付。
