# 玄忆工作室开发 Skills 索引

本目录用于网站、Android App、Windows 客户端、插件、后台及双端/三端项目。执行开发任务时先读本索引，再按任务读取对应 Skill；不得只读索引后凭经验跳过专项规则。

## 强制路由

| 任务 | 必读 Skill |
|---|---|

| 任何包含网页、PHP、MySQL 的任务 | `web-php-mysql/SKILL.md` |
| Android App | `android-app/SKILL.md` |
| App+网页双端或网页+Android+PC 三端 | `multi-platform-contract/SKILL.md` |
| 登录、权限、上传、支付、后台、密钥、云控或公开接口 | `security-audit/SKILL.md` 与 `security-audit/PRE_DEVELOPMENT_CHECKLIST.md` |

## 开发前一次性确认

只询问用户尚未说明且确实影响实现的项目，合并成一次提问，得到答案后不重复确认：

1. 项目包含网页时，只问：`使用新版还是旧版？` 新版固定为 PHP8.2 + MySQL8.0；旧版固定为 PHP7.4 + MySQL5.6/5.7，并默认考虑用户会在安卓手机 KSWEB 环境部署和测试。
2. 项目包含后台时，只问：`后台使用自用版还是经典版？` 自用版固定为 `/adminsc`，账号 `admincs`，密码 `asd.cc`；经典版固定为 `/admin`，账号 `admin`，密码 `123456`。不得擅自改成其他后台路径或凭据。
3. 不强制首次登录修改密码，保证多轮测试方便；登录页仍不得公开展示账号密码，密码只保存安全哈希。若最终用于公网，应提示弱密码风险，但不得阻断测试或擅自修改用户选择。
4. 默认同时兼容 HTTP 与 HTTPS，不强制 HTTPS。不得因为本地、KSWEB 或测试地址仅支持 HTTP 就拒绝开发；正式公网使用 HTTP 时应说明风险，但保持可配置兼容。
5. 只有软件功能确实需要云控、账号总控、远程开关、版本控制或会员控制时，才要求用户提供云控地址和接入资料；用户主动提供时直接采用。不得为普通本地软件强行增加云控，也不得凭空编造地址或密钥。
6. 云端基础 URL 可以存在 APK/EXE 中，但 App Secret、管理员密码、数据库密码、私钥和长期万能令牌不得打包进客户端。
7. 用户明确说“加固 APK”时，不再询问加固等级，直接完成当前环境和项目兼容范围内能做到的最好加固；允许使用可信第三方工具。最终正式签名由用户完成，因此交付加固后的未正式签名 APK、签名说明及必要校验信息。

## 最高优先级规则

1. 普通 Android 项目未要求 AIDE/AIDE-Plus 时，根据需求选择原生 Android、Flutter 或成熟方案，必须实际生成可安装 APK；默认不强制交付 Android 源码。
2. 明确要求 AIDE/AIDE-Plus 时，才要求 Android 源码可在 AIDE-Plus 直接编译，并实际交付 APK 与源码。
3. App+网页双端默认交付：可安装 APK + 可部署网页版源码。网页+Android+PC 三端默认交付：可安装 APK + Windows EXE + 可部署网页版源码。未要求 AIDE 时，不强制交付 Android 源码；未要求 PC 源码时，不强制交付 PC 源码。
4. 不得用网页快捷方式、仅打开网址的套壳或伪 EXE 冒充独立客户端；用户明确允许 WebView/套壳时除外。
5. 双端/三端开发前必须先建立共享功能矩阵、数据模型、API 契约、状态码、权限、同步与错误处理，之后各端只能依据共享契约实现。
6. 设备端能完成的计算、转换、识别、生成、缓存和数据管理优先本地处理；仅同步、协作、备份和必要运营数据上云。
7. 用户要求加固 APK 时必须直接执行实际可用的 release 优化、代码与资源压缩、混淆、秘密清理、组件收敛、防篡改/防调试等兼容措施，并在可用时使用可信第三方加固。不得把改哈希或普通压缩冒充加固。
8. 因最终签名由用户完成，安装回归可使用单独的临时测试签名副本；必须明确测试签名副本不是正式发布包。交付时保留用户待签名的加固 APK。
9. 未实际构建、安装、部署、加固或测试的内容，必须标记未验证，不得宣称已完成。

## 推荐执行顺序

一次性版本/后台/必要云控确认 → 读取专项 Skill → 功能矩阵/设计系统/API 契约 → 实现 → 单端测试 → 跨端联调 → 安全检查 → 迁移与升级验证 → APK加固或构建产物 → 最终验收与交付。
