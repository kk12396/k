# PHP/MySQL 网页开发 Skill

## 开始前只确认两项

任何任务只要包含网页、网站、PHP、MySQL、Web API 或后台，且用户尚未明确，开始开发前合并询问：

1. `使用新版还是旧版？`
2. 若包含后台：`后台使用自用版还是经典版？`

用户已经说明的内容不得重复询问。

## 环境定义

### 旧版

- PHP 7.4
- MySQL 5.6/5.7
- 默认考虑用户会在安卓手机 KSWEB、本地 PHP 环境和共享存储中部署测试。
- 禁止 PHP 8 专属语法、属性、联合类型和不兼容依赖。
- 禁止依赖 MySQL 8 的 CTE、窗口函数、函数索引和新版专属语法。
- 安装器、配置写入、上传、缓存、日志和迁移必须兼容安卓共享存储对 `flock`、`LOCK_EX`、`rename` 原子替换支持不完整的情况。

### 新版

- PHP 8.2
- MySQL 8.0
- 处理动态属性、严格类型、弃用警告和第三方库兼容。
- 使用 MySQL 8 能力时明确字符集、排序规则、SQL 模式和迁移策略。

## 后台模式

### 自用版

- 后台路径：`/adminsc`
- 初始账号：`admincs`
- 初始密码：`asd.cc`

### 经典版

- 后台路径：`/admin`
- 初始账号：`admin`
- 初始密码：`123456`

不得擅自替换为其他默认值。登录页不得展示默认账号密码，数据库中只保存 `password_hash()` 生成的哈希，不保存明文。

默认不强制首次登录修改密码，避免影响多轮测试。若最终部署到公网，应明确提示弱密码风险并建议用户自行修改、增加 IP 限制、登录限速或二次验证，但不得擅自改变用户选择或阻断本地测试。

后台路径不是安全边界。每个后台页面和接口仍须执行登录、角色、对象级权限、CSRF、会话和输入校验。

## HTTP 与 HTTPS

- 默认同时兼容 HTTP 与 HTTPS，不强制 HTTPS。
- 本地地址、局域网地址、KSWEB、临时测试域名或没有证书的环境必须可以正常运行。
- Cookie、回调地址、API 基础地址和资源链接不得硬编码为仅 HTTPS。
- 使用 HTTPS 时自动启用 Secure Cookie 和更严格安全配置；使用 HTTP 时不得错误设置 Secure 导致无法登录。
- 正式公网使用 HTTP 时说明账号、令牌和数据可能被窃听或篡改的风险，但保持用户要求的兼容能力。

## 固定项目规则

- 主目录不使用 `public`。
- 项目包含 `install.php`、`docs/FEATURES.md`、`docs/CHANGELOG.md`、`docs/DEV_PROGRESS.md`。
- 数据库配置、日志、备份、迁移记录和敏感文件必须阻止 Web 直接访问。
- 后台路径跟随自用版或经典版配置，安装器、导航、迁移管理和文档必须保持一致。

## 数据库与迁移

- 所有升级使用可重复执行的幂等增量迁移，老站覆盖新版后只需后台迁移或 `php cli/migrate.php`。
- 不得要求重装、清库、重建库或重新导入 `schema.sql`。
- 新增数据库功能同步更新实际后台路径下的迁移管理器、`cli/migrate.php`、`install.php` 和 `schema.sql`，并共享同一迁移链。
- 迁移需记录版本、校验值、开始/完成状态和失败原因；部分失败时可安全重试。
- 外键、索引长度、字符集、默认值和存储引擎必须按所选 MySQL 版本验证。

## 安装与手机测试

- 安装前检查 PDO/MySQL 扩展、目录可写、数据库权限、表前缀和现有安装状态。
- KSWEB 环境使用实际写入探针、循环写入和写后校验，不用单纯 `is_writable()` 或强制文件锁判断可写。
- 配置更新优先采用兼容写入方案；原子替换失败时安全降级，且不得损坏已有配置。
- 安装失败必须读取受保护日志并给出具体原因，不得只返回模糊错误编号。
- 旧版交付前至少做 PHP7.4 语法检查、MySQL5.6/5.7兼容检查，并记录 KSWEB 未验证项或实测结果。

## 安全底线

使用参数化 SQL、输出转义、CSRF Token、会话轮换、权限校验、上传白名单、路径规范化、速率限制和关键操作审计；错误页不得泄露 SQL、路径、堆栈、配置、默认凭据或数据库结构。
