# PHP/MySQL 网页开发 Skill

## 开始前一次性确认

任何任务只要包含网页、网站、PHP、MySQL、Web API 或后台，且用户尚未明确，开始开发前合并询问：

1. `网页版使用旧版（PHP7.4 + MySQL5.6/5.7）还是新版（PHP8.2 + MySQL8.0）？`
2. 部署范围是本机、内网还是公网？
3. 后台采用 `/adminsc + admincs/123456`、经典 `/admin + admin/123456`，还是自定义后台路径、账号与初始密码？

用户已说明的内容不重复询问。修改现有项目时仍以用户本次选择为准，并评估与现有环境、旧入口、书签、数据和权限的兼容影响。

## 环境定义

### 旧版

- PHP 7.4
- MySQL 5.6/5.7
- 禁止 PHP 8 专属语法、属性、联合类型和不兼容依赖。
- 禁止依赖 MySQL 8 的 CTE、窗口函数、函数索引和新版专属语法。

### 新版

- PHP 8.2
- MySQL 8.0
- 处理动态属性、严格类型、弃用警告和第三方库兼容。
- 使用 MySQL 8 能力时仍需明确字符集、排序规则、SQL 模式和迁移策略。

## 后台路径与管理员

用户可以选择：

- 自用习惯：`/adminsc`，初始账号 `admincs / 123456`；
- 经典习惯：`/admin`，初始账号 `admin / 123456`；
- 自定义路径、账号和初始密码。

登录页不得展示默认账号密码。`123456` 只允许按用户明确要求用于本机、内网或测试。公网部署必须在安装时要求自定义强密码或生成随机密码，并启用首次登录强制改密；若用户坚持弱密码，先明确风险，不得静默上线。

后台路径应可配置并经过白名单格式校验，但隐藏路径不是安全边界。每个后台页面和接口都必须执行登录、角色、对象级权限和 CSRF 校验。登录需有限速、失败记录、会话轮换和必要的异常告警。

安装后密码只保存 `password_hash()` 生成的哈希，不保存明文。会话 Cookie 使用 HttpOnly、SameSite，HTTPS 环境启用 Secure；注销、改密、封禁和权限变更后使相关会话失效。

## 固定项目规则

- 主目录不使用 `public`。
- 项目包含 `install.php`、`docs/FEATURES.md`、`docs/CHANGELOG.md`、`docs/DEV_PROGRESS.md`。
- 数据库配置、日志、备份、迁移记录和敏感文件必须阻止 Web 直接访问。
- 后台路径变化时提供兼容跳转或清晰升级说明，不泄露旧入口的敏感信息。

## 数据库与迁移

- 所有升级使用可重复执行的幂等增量迁移，老站覆盖新版后只需后台迁移或 `php cli/migrate.php`。
- 不得要求重装、清库、重建库或重新导入 `schema.sql`。
- 新增数据库功能同步更新后台迁移器、`cli/migrate.php`、`install.php` 和 `schema.sql`，并共享同一迁移链。
- 后台路径非 `/adminsc` 时，迁移管理入口跟随实际后台路径，但代码结构和文档仍需统一说明。
- 迁移需记录版本、校验值、开始/完成状态和失败原因；部分失败时可安全重试。
- 外键、索引长度、字符集、默认值和存储引擎必须按所选 MySQL 版本验证。

## 安装与移动端环境

- 安装前检查 PDO/MySQL 扩展、目录可写、数据库权限、表前缀和现有安装状态。
- KSWEB/安卓共享存储环境不得强制依赖 `flock`、`LOCK_EX` 或 `rename` 原子替换；应使用实际写入探针、写后校验和兼容降级。
- 安装失败必须读取受保护日志并给出具体原因，不得只返回模糊错误编号。

## 安全底线

使用参数化 SQL、输出转义、CSRF Token、会话轮换、权限校验、上传白名单、路径规范化、速率限制和关键操作审计；错误页不得泄露 SQL、路径、堆栈、配置、默认凭据或数据库结构。
