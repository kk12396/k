# 开发前安全确认清单

只询问用户尚未明确且确实影响实现的项目，并合并成一次提问；用户已说明的内容不得重复询问。

## 标准提问模板

```text
开发前确认以下未明确项：
1. 若包含网页：使用新版还是旧版？新版=PHP8.2+MySQL8.0；旧版=PHP7.4+MySQL5.6/5.7，旧版按安卓手机KSWEB测试兼容处理。
2. 若包含后台：使用自用版还是经典版？自用版=/adminsc，账号admincs，密码asd.cc；经典版=/admin，账号admin，密码123456。
3. 软件是否需要云控？需要时请提供云控地址和接入资料；你也可以主动提供。普通本地软件不强制接入云控。
```

默认规则无需再次询问：

- 不强制首次登录修改密码，方便多轮测试；登录页不得展示账号密码，数据库只保存密码哈希。
- 默认兼容 HTTP 和 HTTPS，不强制 HTTPS；本地、KSWEB、局域网和无证书测试地址可直接使用。
- 用户说“加固 APK”时，直接做当前环境能完成的最好加固，可使用可信第三方工具；正式签名由用户完成。

## 判断规则

- 自用后台固定为 `/adminsc + admincs/asd.cc`；经典后台固定为 `/admin + admin/123456`，不得擅自改值。
- 默认不强制改密。最终公网使用弱密码时必须提示风险，但不得阻断测试或擅自修改用户选择。
- 隐藏后台路径只能降低扫描噪声，不能替代登录限速、CSRF、权限校验、会话安全和审计日志。
- 默认允许 HTTP/HTTPS 双兼容。使用 HTTP 时不得错误设置 Secure Cookie；正式公网 HTTP 需说明窃听和篡改风险。
- 只有功能确实需要云控时才索取云控资料，不得为本地工具强行增加云控。
- 云端基础 URL 通常不是秘密；可公开 App Key 可放客户端。App Secret、管理员密码、数据库密码、私钥和长期万能令牌必须只保留在服务端。
- 客户端使用用户登录、设备注册、短期访问令牌、刷新令牌、服务端权限校验和必要的重放防护。

## 用户要求 APK 加固时

直接执行，不再只给规划，也不再询问加固等级：

1. 生成 release APK，关闭 debuggable 和测试配置。
2. 启用兼容的代码/资源压缩、优化、混淆，并补齐反射、JNI、序列化、插件和模型保留规则。
3. 移除敏感日志、测试接口、演示凭据、秘密字符串和无用导出组件。
4. 检查 HTTP 白名单、备份策略、本地令牌存储、WebView、深链和组件导出。
5. 在兼容前提下加入防调试、防篡改、完整性校验、签名校验和关键逻辑最小暴露。
6. 有可信且兼容的第三方工具时实际执行第三方加固；没有时交付当前环境可实现的最高强度内置加固。
7. 正式签名由用户完成，默认交付 `*-hardened-unsigned.apk`、签名说明和校验信息。
8. 如需安装回归，可额外生成明确标记的临时 `test-signed` 副本；不得冒充正式签名包。
9. 输出加固前后 SHA-256、大小、版本、加固方式、测试结果和未验证项。

不得把改文件名、改哈希、压缩 ZIP、简单字符串拆分或仅启用普通 R8 宣称为完整第三方壳加固。
