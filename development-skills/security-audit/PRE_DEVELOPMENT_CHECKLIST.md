# 开发前安全确认清单

仅询问用户尚未明确且会影响实现的项目，并合并成一次提问；用户已说明的内容不得重复询问。

## 标准提问模板

```text
开发前确认以下未明确项：
1. 部署范围：仅本机、内网，还是公网？
2. 若包含网页：使用旧版（PHP7.4 + MySQL5.6/5.7）还是新版（PHP8.2 + MySQL8.0）？
3. 后台配置：使用 /adminsc + admincs/123456、经典 /admin + admin/123456，还是自定义后台路径、账号和初始密码？公网环境建议自定义强密码并首次登录强制改密。
4. App 云端配置：云端基础地址是什么，是否使用 HTTPS，地址固定打包还是允许用户配置？是否已有 App Key、用户登录或设备注册方案？任何 App Secret、管理员密码或长期万能令牌都不应打包进 APK。
5. Android 发布安全：使用默认发布安全、加强加固，还是指定第三方加固？是否已有正式签名证书？
```

## 判断规则

- 云端基础 URL 通常不是秘密，可以随 APK 被反编译看到；不能依靠隐藏 URL 保护接口。
- 可公开的 App Key 可放客户端；能直接授权敏感操作的 App Secret、数据库密码、管理员密码和长期静态令牌必须只保留在服务端。
- 客户端使用用户登录、设备注册、短期访问令牌、刷新令牌、服务端权限校验和必要的请求重放防护。
- 弱初始密码只允许按用户明确要求用于本机、内网或测试。公网部署需自定义强密码或生成随机密码，并首次登录强制改密。
- `/adminsc` 或其他自定义路径只能降低自动扫描噪声，不是身份认证和权限控制。
- 默认发布安全无需用户选择，始终启用；“加强加固/第三方加固”才需要确认兼容性、签名和工具。

## 用户要求 APK 加固时

直接执行以下流程，不再只给规划：

1. 生成 release APK，关闭 debuggable 和测试配置。
2. 启用适合项目的代码压缩、资源压缩、优化和混淆，保留必要反射/JNI/序列化规则。
3. 移除敏感日志、测试接口、调试证书、演示账号和无用导出组件。
4. 检查明文 HTTP、备份策略、网络安全配置、本地令牌存储、WebView 和组件导出。
5. 使用正式证书签名并验证签名、包名、版本和安装升级。
6. 若用户指定第三方壳且当前环境有可信工具，实际执行壳加固、重新签名并安装回归；否则明确说明第三方壳未执行。
7. 输出加固前后 APK、签名信息、映射文件保管说明、测试结果和未验证项。

不得把改文件名、改哈希、压缩 ZIP、简单字符串拆分或仅启用 R8 宣称为完整第三方壳加固。
