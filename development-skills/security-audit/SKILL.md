# 应用安全审计 Skill

## 开发前一次性确认

先读取 `PRE_DEVELOPMENT_CHECKLIST.md`。只询问用户未说明且会影响实现的内容，并合并成一次提问：部署范围、本机/内网/公网、网页版本、后台路径与初始账号、App 云端地址与 HTTPS、认证方式、APK 发布安全等级和签名证书。

## 基本原则

- 默认拒绝、最小权限、服务端最终裁决、敏感数据最少收集和安全失败。
- 前端、APK、EXE 中的限制都不能替代服务端权限校验。
- 不使用硬编码密钥、默认开放调试、万能令牌、隐藏接口或客户端可逆“加密”保护核心秘密。
- 隐藏后台路径、混淆云端 URL、字符串拆分和 APK 加固只能提高攻击成本，不能替代认证、授权、TLS、限速和审计。

## 后台路径与初始管理员

用户可在开发前选择：

- `/adminsc`，初始账号 `admincs / 123456`；
- 经典 `/admin`，初始账号 `admin / 123456`；
- 自定义后台路径、账号和初始密码。

以上弱密码仅按用户明确要求用于本机、内网或测试。公网部署必须要求自定义强密码或生成随机密码，并启用首次登录强制改密。若用户坚持在公网使用弱密码，先明确风险，并建议至少增加 IP 白名单、登录限速、二次验证和异常告警；不得静默部署。

登录页不得展示默认账号密码。安装完成后只保存安全密码哈希，不保存明文密码；会话 Cookie 使用 HttpOnly、SameSite，并在 HTTPS 环境启用 Secure。后台路径不是安全边界，所有后台请求都必须独立完成登录、权限、CSRF 和对象级授权检查。

## App 云端地址与客户端秘密

- 云端基础 URL 通常可以打包进 APK，它会被反编译或从流量中看到，因此不要把“隐藏地址”作为安全方案。
- 可公开的 App Key、环境标识和 API 版本可以放客户端。
- App Secret、管理员密码、数据库密码、私钥和长期万能令牌必须只保留在服务端。
- App 使用用户登录、设备注册、短期访问令牌、刷新令牌、服务端权限校验、速率限制和必要的重放防护。
- 本地令牌使用系统安全存储；退出、封禁、过期、换密和设备解绑时服务端可立即失效。
- 正式环境优先 HTTPS，并默认禁止无必要的明文 HTTP；证书固定只有在具备备份密钥、轮换和恢复方案时采用。

## 必查范围

### 身份与权限

检查密码哈希、登录限速、会话固定、令牌刷新、退出失效、角色越权、对象级越权、设备绑定、封禁、会员到期和后台二次校验。每个数据读写接口都要验证当前用户是否拥有目标资源。

### 输入与输出

使用参数化 SQL；HTML 输出按上下文转义；富文本白名单清洗；所有修改请求使用 CSRF 防护；校验长度、类型、范围、枚举、编码和业务状态。错误响应不得泄露 SQL、目录、堆栈、密钥或内部逻辑。

### 文件与路径

校验扩展名、MIME、文件头、大小、数量、压缩炸弹、文件名和保存路径；上传目录禁止执行脚本；下载必须鉴权；防止路径穿越、任意覆盖、符号链接绕过和临时文件泄露。

### API 与网络

统一鉴权、时间戳/重放防护、幂等、速率限制、请求大小限制、超时和审计日志。生产环境优先 HTTPS；确需 HTTP 时明确风险并限制敏感操作和传输数据。

### Android/PC

敏感令牌放入系统安全存储；日志不得打印账号、令牌、文件内容或完整接口响应；导出组件、深链、WebView、文件 URI、剪贴板和本地数据库均需审查。禁止未经验证加载远程代码或远控逻辑。

### 数据与隐私

明确本地/云端数据边界、备份内容、保留期限、删除机制和导出机制。个人数据上传前最小化，必要时加密；用户删除账号时处理云端数据、设备令牌和备份副本。

## APK 加固审计

默认 release 安全必须包含关闭调试、移除敏感日志、代码/资源压缩与混淆、最小导出组件、正式签名、明文流量限制和秘密扫描。

用户明确要求“加固 APK”时，直接执行可用的内置加强加固，并在可信工具可用时执行第三方壳加固。完成后必须重新签名或按服务流程签名，并回归安装、升级、启动、网络、推送、JNI/模型、文件和核心流程。无法执行第三方壳时明确说明，不得把普通混淆冒充壳加固。

## 安全交付

交付前输出安全检查表，列出已修复风险、剩余风险、未验证项、签名/加固状态和高风险操作。发现严重越权、密钥泄露、任意文件执行或注入风险时，优先阻断发布并修复根因。
