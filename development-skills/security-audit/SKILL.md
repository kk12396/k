# 应用安全审计 Skill

## 开发前确认

先读取 `PRE_DEVELOPMENT_CHECKLIST.md`。只询问用户尚未明确且确实影响实现的内容：网页新版/旧版、后台自用版/经典版，以及软件确实需要云控时的云控地址和接入资料。

## 基本原则

- 默认拒绝、最小权限、服务端最终裁决、敏感数据最少收集和安全失败。
- 前端、APK、EXE 中的限制不能替代服务端权限校验。
- 不使用硬编码 App Secret、管理员密码、数据库密码、私钥或长期万能令牌。
- 隐藏后台路径、混淆 URL、字符串拆分和 APK 加固只能提高攻击成本，不能替代认证、授权、限速和审计。
- 默认兼容 HTTP 与 HTTPS，不强制 HTTPS；正式公网 HTTP 需提示风险，但不得阻断本地和多轮测试。

## 后台模式

### 自用版

- 路径：`/adminsc`
- 账号：`admincs`
- 初始密码：`asd.cc`

### 经典版

- 路径：`/admin`
- 账号：`admin`
- 初始密码：`123456`

不强制首次登录修改密码，以方便多轮测试。登录页不得展示默认账号密码，服务端只保存安全密码哈希。最终公网使用弱密码时要明确提示风险，并建议登录限速、IP限制、二次验证或用户自行改密，但不得擅自修改凭据或阻断测试。

后台路径不是安全边界，所有后台请求仍须执行登录、角色、对象级权限、CSRF、会话和输入校验。

## 云控与客户端配置

- 只有功能确实需要账号总控、会员、远程开关、版本控制、设备绑定或到期控制时，才要求用户提供云控地址和接入资料；用户主动提供时直接采用。
- 普通本地工具不得强行增加云控，也不得编造云控地址、App Secret 或有效凭据。
- 云端基础 URL 通常可放 APK/EXE，也可做成配置项；真正秘密必须只保留在服务端。
- 客户端使用用户登录、设备注册、短期访问令牌、刷新令牌和服务端权限校验。
- 默认允许 HTTP/HTTPS 双兼容；HTTP 仅按实际地址放行必要域名，不应无条件全局放开明文流量。
- 使用 HTTPS 时启用更严格 Cookie 和传输配置；使用 HTTP 时避免 Secure Cookie 导致登录失败。

## 必查范围

### 身份与权限

检查密码哈希、登录限速、会话固定、令牌刷新、退出失效、角色越权、对象级越权、设备绑定、封禁、会员到期和后台二次校验。每个数据读写接口都要验证当前用户是否拥有目标资源。

### 输入与输出

使用参数化 SQL；HTML 输出按上下文转义；富文本白名单清洗；修改请求使用 CSRF 防护；校验长度、类型、范围、枚举、编码和业务状态。错误响应不得泄露 SQL、目录、堆栈、密钥或内部逻辑。

### 文件与路径

校验扩展名、MIME、文件头、大小、数量、压缩炸弹、文件名和保存路径；上传目录禁止执行脚本；下载必须鉴权；防止路径穿越、任意覆盖、符号链接绕过和临时文件泄露。

### API 与网络

统一鉴权、幂等、速率限制、请求大小限制、超时和审计日志。需要时加入时间戳或重放防护。HTTP/HTTPS 均需处理错误、超时、地址切换和令牌失效。

### Android/PC

敏感令牌放入系统安全存储；日志不得打印账号、令牌、文件内容或完整接口响应；导出组件、深链、WebView、文件 URI、剪贴板和本地数据库均需审查。禁止未经验证加载远程代码或远控逻辑。

### 数据与隐私

明确本地/云端数据边界、备份内容、保留期限、删除机制和导出机制。个人数据上传前最小化，必要时加密；用户删除账号时处理云端数据、设备令牌和备份副本。

## APK 加固审计

用户明确要求“加固 APK”时，直接执行当前环境和项目兼容范围内能实现的最好加固，可使用可信第三方工具，不再询问加固等级。

至少包括 release 优化、代码与资源压缩、混淆、敏感信息清理、最小导出组件、防调试、防篡改、完整性/签名校验和兼容回归。第三方工具可用且兼容时实际执行；不可用时明确交付最高可实现的内置加固版本。

最终正式签名由用户完成。默认交付未正式签名的加固 APK、签名说明和校验信息；可额外制作临时测试签名副本用于安装回归，但必须明确不是正式发布包。

## 安全交付

交付前输出安全检查表，列出后台模式、HTTP/HTTPS兼容状态、云控接入状态、已修复风险、剩余风险、APK加固层级、签名状态和未验证项。发现严重越权、密钥泄露、任意文件执行或注入风险时，优先修复根因。
