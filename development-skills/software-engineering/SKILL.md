# 正式软件工程 Skill

## 工作原则

- 需求明确时直接执行，不把正式项目降级为 Demo、静态原型或无法运行的示例。
- 先理解现有项目、功能与数据，再增量修改；不得为了方便整体推翻、清库或删除旧功能。
- 不以“代码已生成”等同于“功能已完成”。完成必须有对应构建、测试、安装或部署证据。
- 不能执行的步骤要明确记录为未验证，并继续完成其他可执行项。

## 新项目流程

1. 提取目标用户、核心场景、功能边界、数据归属、权限、平台和交付物。
2. 建立功能清单、非功能要求、异常场景和验收标准。
3. 涉及 UI 时先建立设计系统；涉及多端时先建立共享契约。
4. 设计目录、模块边界、数据模型、接口、状态码和日志策略。
5. 先实现最短完整业务闭环，再扩展次要功能；每个模块同时补齐错误、空、加载和恢复状态。
6. 编写测试、安装说明、变更记录和可重复构建方式。

## 修复流程

1. 复现：记录入口、操作步骤、设备/环境、输入、预期和实际结果。
2. 取证：读取日志、堆栈、网络响应、数据库状态和相关代码，不凭错误编号猜根因。
3. 根因：区分直接原因、触发条件和系统性原因；定位同类代码是否也受影响。
4. 影响：评估旧数据、旧版本、其他页面、其他端和迁移链。
5. 修复：在最小影响面内修根因，不用吞异常、硬编码或删除校验掩盖问题。
6. 回归：验证原问题、关联功能、旧功能、异常路径和升级路径。

## 升级规则

- 更新前先读 `docs/FEATURES.md`、现有迁移、配置、安装器和变更记录。
- 保留旧数据、配置、权限、入口、操作习惯和兼容接口；确需替换时说明替换原因、迁移方式和影响。
- 新旧客户端/API 并存时提供版本协商、兼容期和明确错误，不让旧端静默损坏数据。
- 废弃功能先标记“已替换/已废弃”，不得直接从文档与代码中无记录消失。

## 完成定义

至少核对：功能矩阵、语法、依赖、路径、构建、安装/部署、数据迁移、权限、安全、异常恢复、备份还原、旧功能和正式文案。最终报告必须列出已完成、已验证、未验证、已知限制、测试结果和用户需要执行的操作。
