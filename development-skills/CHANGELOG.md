# CHANGELOG

## v1.2.0 - 2026-07-28

### 修改

- 网页开发确认简化为“新版还是旧版”：新版固定 PHP8.2 + MySQL8.0；旧版固定 PHP7.4 + MySQL5.6/5.7。
- 旧版默认按安卓手机 KSWEB、本地 PHP 和共享存储环境进行兼容设计与测试。
- 后台确认简化为“自用还是经典”：自用固定 `/adminsc + admincs/asd.cc`；经典固定 `/admin + admin/123456`。
- 默认不强制首次登录修改密码，保证多轮测试方便；登录页仍不得展示凭据，数据库只保存密码哈希。
- 默认兼容 HTTP 与 HTTPS，不强制 HTTPS；本地、局域网、KSWEB 和无证书测试地址可使用。
- 云控改为按需接入：只有功能确实需要时才索取云控地址和资料，用户主动提供时直接采用。
- 用户说“加固 APK”时不再询问加固等级，直接执行当前环境和项目兼容范围内能做到的最好加固，可使用可信第三方工具。
- APK 最终正式签名改由用户完成；默认交付 `hardened-unsigned APK`、签名/对齐说明和校验信息。
- 安装回归允许额外生成明确标记的临时 `test-signed` 副本，但不得冒充正式发布包。

### 安全说明

- 云端 URL 和可公开 App Key 可以存在客户端；App Secret、管理员密码、数据库密码、私钥和长期万能令牌必须只保留在服务端。
- 公网使用弱密码或 HTTP 时必须提示风险，但不得阻断本地测试或擅自修改用户选择。

## v1.1.0 - 2026-07-28

### 新增

- 开发前一次性安全确认模板。
- 部署范围确认：本机、内网或公网。
- 后台配置选项：`/adminsc + admincs/123456`、经典 `/admin + admin/123456` 或自定义。
- App 云端 URL、HTTPS、认证、客户端秘密和签名证书确认。
- APK 默认发布安全、内置加强加固和第三方壳加固的分级规则。
- APK 加固后的签名、安装、升级和核心流程回归要求。

### 修改

- 云端 URL 不再被错误视为秘密；明确真正秘密必须只保留在服务端。
- 弱初始密码仅允许按用户要求用于本机、内网或测试，公网不得静默使用。
- 用户明确要求“加固 APK”时必须直接执行当前环境可完成的加固流程，不得只给方案。
- 明确区分 R8/混淆与第三方壳加固，禁止夸大完成状态。
