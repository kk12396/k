# CHANGELOG

## v1.3.2 - 2026-07-30

### 网站安装与数据库表前缀

- 所有网站 `install.php` 必须提供可编辑的数据库表前缀，给出项目专用默认值并允许用户修改。
- 表前缀仅允许字母、数字和下划线，执行长度、格式及同前缀表冲突检查。
- 安装器、业务查询、模型、迁移、CLI、备份恢复、表检测、外键、索引、视图和清理脚本统一使用表名解析器，禁止硬编码完整物理表名。
- `schema.sql` 使用前缀占位符或安装器安全替换，迁移记录表跟随当前前缀。
- 旧站升级必须沿用原表前缀，不得恢复默认前缀、静默改前缀或另建一套空表。
- 修改表前缀必须使用独立迁移工具，先备份、检查冲突并支持回滚，不得混入普通版本升级。
- 发布前新增默认前缀、自定义前缀、旧站原前缀、重复迁移和备份恢复验证。
- INDEX、完整个性化指令、Web Skill、发布迁移 Skill 和 README 已同步升级。

## v1.3.1 - 2026-07-28

### 系统化修 Bug 强化

- 将原有基础调试规则升级为完整系统化调试流程，参考 `obra/superpowers` 的 Systematic Debugging、Root Cause Tracing 与 Verification Before Completion。
- 新增硬规则：未完成根因调查不得直接改代码；每轮只验证一个明确假设；没有当前版本的新鲜证据不得宣称修复完成。
- 新增“连续三次失败停止门禁”：同一问题三次修复失败后，禁止继续堆叠第4个补丁，必须提交阶段报告并复查架构、共享状态、依赖、版本和环境。
- 新增多组件边界取证、调用链反向追踪、正常样例对比、单变量最小实验和失败测试优先规则。
- 新增用户反馈“还是报错、又错了、别再猜”时的强制处理：停止旧猜测、汇总失败尝试、重新读取最新代码与日志、隔离无效补丁。
- 新增 Android、PHP/MySQL、KSWEB、双/三端和 APK 加固后的专项验证清单。

### 新增文件

- `testing-debugging/ROOT_CAUSE_TRACING.md`：从报错位置反向追踪到最初错误输入或状态。
- `testing-debugging/VERIFICATION_GATE.md`：没有完整构建、安装/部署和原始复现证据，不得宣布完成。
- `testing-debugging/BUG_SESSION_REPORT.md`：连续修复失败时的证据、假设、尝试和卡点报告模板。
- `testing-debugging/SOURCE_NOTICE.md`：上游来源和 MIT 许可说明。

### 路由与自定义指令

- INDEX 将所有报错、闪退、卡顿、构建/安装失败和连续修复失败强制路由至新版调试 Skill。
- 完整个性化指令加入根因调查、单一假设、三次失败停止和验证门禁，避免 AI 反复输出未经验证的补丁。

## v1.3.0 - 2026-07-28

### 重构

- 将完整个性化自定义指令重构为“GitHub索引负责详细规则，自定义指令保留入口、固定偏好和交付底线”，减少重复加载、无效指令和版本冲突。
- 明确只按 INDEX 路由读取当前任务相关 Skill，禁止无关模块占用上下文，也不向用户复述整份 Skill。
- 完整补齐需求执行、旧项目增量更新、UI、网页版本、KSWEB、后台模式、HTTP/HTTPS、可选云控、安全、双/三端共享契约、数据库迁移和最终验收规则。

### Android签名与加固

- Android 主要交付物必须为已经签名、可直接安装使用的 APK，不得只交未签名包或等待用户二次签名的包。
- 已有应用必须沿用用户原签名，保证覆盖升级和应用内签名校验正常。
- 新项目无签名时生成项目独立 release 签名，用其完成最终 APK 签名，并将签名文件、别名、密码、证书 SHA-256 指纹、有效期和备份说明放入私密交付包交给用户。
- 签名文件不得上传公开 GitHub、不得放入公开源码、不得跨项目复用，也不得由 AI 独占或扣留。
- 用户要求加固 APK 时，加固后必须使用同一份交付签名完成最终签名、签名验证、直接安装和同签名覆盖升级测试。
- 防篡改和签名证书白名单必须绑定用户持有的交付签名，不得绑定用户无法取得的开发方私有签名。

## v1.2.1 - 2026-07-28

- 所有 Android APK 主要交付物必须已经签名、可直接安装使用，不得只交未签名 APK。
- 修改已有应用时必须沿用用户原签名，保证覆盖升级和应用内签名校验正常。
- 新项目且用户没有签名文件时，生成项目独立 release 签名，用其完成最终 APK 签名，并将签名文件、别名、密码、证书指纹和备份说明放入私密交付包交给用户。

- 防篡改、签名校验和证书白名单必须绑定用户能持有的签名，不能绑定用户拿不到的开发方私有签名。
- 增加同签名覆盖升级验证，确保用户以后可以继续发布更新。

## v1.2.0 - 2026-07-28

### 修改

- 网页开发确认简化为“新版还是旧版”：新版固定 PHP8.2 + MySQL8.0；旧版固定 PHP7.4 + MySQL5.6/5.7。
- 旧版默认按安卓手机 KSWEB、本地 PHP 和共享存储环境进行兼容设计与测试。
- 后台确认简化为“自用还是经典”：自用固定 `/adminsc + admincs/asd.cc`；经典固定 `/admin + admin/123456`。
- 默认不强制首次登录修改密码，保证多轮测试方便；登录页仍不得展示凭据，数据库只保存密码哈希。
- 默认兼容 HTTP 与 HTTPS，不强制 HTTPS；本地、局域网、KSWEB 和无证书测试地址可使用。
- 云控改为按需接入：只有功能确实需要时才索取云控地址和资料，用户主动提供时直接采用。
- 用户说“加固 APK”时不再询问加固等级，直接执行当前环境和项目兼容范围内能做到的最好加固，可使用可信第三方工具。
- APK 最终正式签名改由用户完成；默认交付 `hardened-unsigned APK`、签名/对齐说明和校验信息。此规则已在 v1.2.1 修正。
- 安装回归允许额外生成明确标记的临时 `test-signed` 副本，但不得冒充正式发布包。此规则已在 v1.2.1 调整为正式交付项目签名和已签名 APK。

### 安全说明

- 云端 URL 和可公开 App Key 可以存在客户端；App Secret、管理员密码、数据库密码、私钥和长期万能令牌必须只保留在服务端。
- 公网使用弱密码或 HTTP 时必须提示风险，但不得阻断本地测试或擅自修改用户选择。
