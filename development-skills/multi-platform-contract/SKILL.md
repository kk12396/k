# 双端/三端共享契约 Skill

## 开发前只确认未明确项

1. 网页使用新版还是旧版：新版固定为 PHP8.2 + MySQL8.0；旧版固定为 PHP7.4 + MySQL5.6/5.7，并按安卓手机 KSWEB 测试兼容处理。
2. 后台使用自用版还是经典版：自用版为 `/adminsc + admincs/asd.cc`；经典版为 `/admin + admin/123456`。
3. 只有项目确实需要云控时，才要求用户提供云控地址和接入资料；用户主动提供时直接采用。

默认不强制首次登录改密，不强制 HTTPS，默认兼容 HTTP 和 HTTPS。最终公网使用弱密码或 HTTP 时提示风险，但不得阻断本地和多轮测试。

## 默认交付边界

### App + 网页双端

- 可安装 Android APK。
- 按用户选择环境完整可部署的网页版源码。
- 未要求 AIDE/AIDE-Plus 时，不强制交付 Android 源码。
- 明确要求 AIDE/AIDE-Plus 时，交付 APK 和可在 AIDE-Plus 直接编译的 Android 源码。

### 网页 + Android + Windows 三端

- 可部署网页版源码。
- 可安装 Android APK。
- 可直接运行或安装的 Windows EXE。
- 未要求 AIDE/AIDE-Plus 时，不强制交付 Android 源码；未明确要求 PC 源码时，不强制交付 PC 源码。
- 不得用网页快捷方式、仅打开网址的伪客户端或改后缀文件冒充 APK/EXE；用户明确要求 WebView/套壳方案时除外。

## 开发前必须建立的共享契约

1. 功能矩阵：每项功能标记 Web、Android、PC 的支持范围、入口、权限和验收条件。
2. 数据模型：字段、类型、默认值、必填、唯一性、时间、删除策略和本地/云端归属。
3. API 契约：路径、方法、鉴权、请求、响应、分页、文件、状态码、错误码、幂等键和版本号。
4. 账户权限：注册、登录、退出、令牌刷新、设备绑定、角色、封禁、过期和离线状态。
5. 同步规则：增量游标、时间基准、软删除、冲突检测、冲突解决、重试、去重和最终一致性。
6. 版本兼容：最低客户端版本、服务端兼容期、强制/可选升级、数据迁移和回滚。
7. 错误处理：同一错误在各端使用统一错误码和业务含义，各端可采用符合平台习惯的展示方式。
8. 安全边界：明确可公开配置、客户端令牌、服务端秘密、后台权限、HTTP/HTTPS、签名/验签、限速和审计责任。

共享契约是唯一事实来源。任何一端变更字段、状态、安全策略或业务规则时，必须先更新契约，再同步实现和测试其他端。

## 云控规则

- 普通本地软件不强制云控。
- 项目需要账号总控、会员、远程开关、设备绑定、到期控制、公告或版本控制时，向用户索取云控地址、App Key/应用标识、环境和必要接口资料。
- 云控基础 URL 和可公开 App Key 可以存在客户端；App Secret、管理员密码、数据库密码、私钥和长期万能令牌只保留在服务端。
- 客户端通过用户登录、设备注册和短期令牌访问云控，普通客户端不得持有管理员能力。
- 默认兼容 HTTP/HTTPS；HTTP 地址按实际域名或 IP 精确放行，不全局无条件开放。

## 本地优先

设备端能完成的计算、转换、识别、生成、缓存、索引、预览、导入导出和个人数据管理优先在本地进行，减少云端存储、带宽和计算压力。仅账号同步、跨端协作、备份恢复、运营控制及无法在设备端完成的任务使用云端。

必须说明哪些数据只在本地、哪些会上云、上传时机、保留期限、缓存清理、云端删除、备份恢复和隐私设置。断网时本地功能应尽量可用；恢复网络后按契约同步。

## APK 加固与签名

所有正式 APK 默认执行 release 安全。用户说“加固 APK”时，直接完成当前环境和项目兼容范围内能做到的最好加固，可使用可信第三方工具，不再询问加固等级。

最终正式签名由用户完成。默认交付 `*-hardened-unsigned.apk`、签名/对齐说明和校验信息；如需安装回归，可额外生成明确标记的临时测试签名副本，不能冒充正式发布包。

## 联调清单

逐项验证注册登录、权限、同步、离线修改、删除、冲突、重复提交、重试、分页、上传下载、大文件、断点恢复、令牌过期、HTTP/HTTPS、服务端升级、旧客户端、后台模式、云控地址异常、APK加固后兼容和异常退出。每项功能在功能矩阵中记录各端结果，未验证项不得标记完成。
