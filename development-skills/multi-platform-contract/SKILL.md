# 双端/三端共享契约 Skill

## 开始前一次性确认

只询问用户尚未明确的项目，并合并成一次提问：

1. 网页使用旧版（PHP7.4 + MySQL5.6/5.7）还是新版（PHP8.2 + MySQL8.0）。
2. 部署范围是本机、内网还是公网。
3. 后台使用 `/adminsc + admincs/123456`、经典 `/admin + admin/123456`，还是自定义路径和初始账号密码。
4. App/PC 的云端基础地址、是否 HTTPS、地址固定打包还是允许配置，以及登录/设备注册方式。
5. Android 是否需要默认发布安全、加强加固或指定第三方壳，是否已有正式签名证书。

云端 URL 和可公开 App Key 可以存在客户端；任何 App Secret、管理员密码、数据库密码、私钥或长期万能令牌不得进入 APK、EXE 或网页前端资源。

## 默认交付边界

### App + 网页双端

- 可安装 Android APK。
- 按用户选择环境完整可部署的网页版源码。
- 未要求 AIDE/AIDE-Plus 时，不强制交付 Android 源码。
- 明确要求 AIDE/AIDE-Plus 时，交付 APK 和可在 AIDE-Plus 直接编译的 Android 源码。

### 网页 + Android + Windows 三端

- 可部署网页版源码。
- 可安装 Android APK。
- 可直接运行或安装的 Windows EXE。
- 未要求 AIDE/AIDE-Plus 时，不强制交付 Android 源码；未明确要求 PC 源码时，不强制交付 PC 源码。
- 不得用网页快捷方式、仅打开网址的伪客户端或改后缀文件冒充 APK/EXE；用户明确要求 WebView/套壳方案时除外。

## 开发前必须建立的共享契约

1. 功能矩阵：每项功能标记 Web、Android、PC 的支持范围、入口、权限和验收条件。
2. 数据模型：字段、类型、默认值、必填、唯一性、时间、删除策略和本地/云端归属。
3. API 契约：路径、方法、鉴权、请求、响应、分页、文件、状态码、错误码、幂等键和版本号。
4. 账户权限：注册、登录、退出、令牌刷新、设备绑定、角色、封禁、过期和离线状态。
5. 同步规则：增量游标、时间基准、软删除、冲突检测、冲突解决、重试、去重和最终一致性。
6. 版本兼容：最低客户端版本、服务端兼容期、强制/可选升级、数据迁移和回滚。
7. 错误处理：同一错误在各端使用统一错误码和业务含义，各端可采用符合平台习惯的展示方式。
8. 安全边界：明确可公开配置、客户端令牌、服务端秘密、后台权限、签名/验签、限速和审计责任。

共享契约是唯一事实来源。任何一端变更字段、状态、安全策略或业务规则时，必须先更新契约，再同步实现和测试其他端，禁止各端自行猜测。

## 客户端认证与云控

- 客户端通过用户登录、设备注册和短期访问令牌访问 API；长期秘密只在服务端。
- App/PC 中的限制不能替代服务端权限校验，客户端可被修改、调试或重放。
- 云控开关、会员、封禁、版本和设备限制由服务端签名/鉴权后返回，客户端验证响应完整性并处理离线策略。
- 管理员操作只能从后台登录会话或受保护管理 API 执行，不复用普通客户端静态密钥。
- 若允许切换云端地址，需防止任意地址注入、明文降级和恶意证书；可限制为可信域名或对配置进行签名。

## 本地优先

设备端能完成的计算、转换、识别、生成、缓存、索引、预览、导入导出和个人数据管理优先在本地进行，减少云端存储、带宽和计算压力。仅账号同步、跨端协作、备份恢复、运营控制及无法在设备端完成的任务使用云端。

必须说明：哪些数据只在本地、哪些会上云、上传时机、保留期限、缓存清理、云端删除、备份恢复和隐私设置。断网时本地功能应尽量可用；恢复网络后按契约同步。

## APK 发布与加固

所有正式 APK 默认执行 release 安全。用户明确要求“加固 APK”时，直接完成可用的内置加强加固、签名和安装回归；可信第三方壳工具实际可用时再执行壳加固。无法执行第三方壳时必须明确标记，不能把普通混淆当作完整壳加固。

## 联调清单

逐项验证注册登录、权限、同步、离线修改、删除、冲突、重复提交、重试、分页、上传下载、大文件、断点恢复、令牌过期、服务端升级、旧客户端、后台改密、云端地址异常、签名/加固后安装和异常退出。每项功能在功能矩阵中记录各端结果，未验证项不得标记完成。
