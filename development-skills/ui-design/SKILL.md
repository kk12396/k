# 产品 UI/UX Skill

## 必读资料

开发前读取精选多风格 UI Skill：

https://raw.githubusercontent.com/kk12396/k/main/ui-style-library/SKILL.md

读取失败必须说明，不得假装已读。

## 强制流程

1. 分析产品定位、目标用户、核心场景、内容密度、设备、品牌气质、性能和无障碍要求。
2. 研究同类大厂应用、应用商店头部产品和成熟设计系统，提炼结构与交互规律，不照搬品牌外观。
3. 从精选 Skill 中选择一个主风格；必要时只增加一个辅助风格或微交互体系，禁止无规则混搭。
4. 编码前建立设计令牌：颜色、字体、字号、行高、间距、圆角、边框、阴影、图标、动效、层级、断点和状态色。
5. 定义导航、信息架构、核心组件和默认/按下/焦点/禁用/加载/空/错误/成功/离线等完整状态。
6. 交付前执行移动端安全区、响应式、无障碍、深色模式、低性能设备和图标审查。

## 视觉约束

- 禁止俗套渐变紫成为默认方案，禁止通用 AI 机器人、悬浮光球和模板化“AI 感”。
- 暖黄、米白、大圆角、轻阴影可以使用，但不得默认或优先使用；必须由产品定位和同类产品研究决定。
- 不得把每个区域都做成同样的大圆角卡片；用排版、分组、留白、边框和层级共同组织信息。
- App 图标必须简洁、缩小可辨。Android 使用前景/背景分离的自适应图标，主体位于安全区并兼容常见蒙版。
- 缺 UI 或素材时自行补齐，优先统一风格 SVG；图标不得混用线性、填充、拟物和表情符号。

## 移动端安全区

背景允许延伸至系统栏，但标题、按钮、列表、输入框和正文必须从安全区内开始；不得与状态栏时间、电量、信号、刘海、挖孔、底部导航栏或手势条重叠。禁止用单一固定顶部间距假装适配所有机型。

## 高保真参考图

用户提供开发图时以图为最终视觉标准，尽量 1:1 还原布局、比例、颜色、间距、字号、图标、交互、状态和页面结构；不得只套主题色或使用通用模板替代。
