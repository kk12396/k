# 发布、迁移与交付 Skill

## 版本与文档

- 使用语义化版本或项目既有版本规则，压缩包、APK、EXE 和文档中的版本保持一致。
- 项目必须维护 `docs/FEATURES.md`、`docs/CHANGELOG.md`、`docs/DEV_PROGRESS.md`；Web 项目包含 `install.php`。
- 更新前读取 FEATURES，更新后只追加、补充或修正；废弃功能标记“已替换/已废弃”。
- CHANGELOG 记录新增、修改、修复、安全、数据库、兼容性、加固和升级操作。

## 数据库迁移

- 每个迁移有唯一版本、幂等检测、事务边界、失败日志和安全重试策略。
- 已执行历史迁移不得随意改内容导致校验值变化；需修正时新增补丁迁移。
- 升级路径至少验证：全新安装、上一版本升级、重复执行、部分失败后重试和旧数据保留。
- Web 新增数据库功能同步更新实际后台路径下的迁移器、CLI 迁移、安装器和 `schema.sql`。

## 构建产物

- Android：交付实际构建的 APK；明确要求 AIDE 时另交 AIDE-Plus 可编译源码。
- App+网页双端：APK + 可部署网页版源码。
- 网页+Android+PC 三端：APK + Windows EXE + 可部署网页版源码。
- Android/PC 源码仅在用户明确要求，或明确要求 AIDE/AIDE-Plus 时按约定交付。
- 不得用快捷方式、空壳、改后缀文件或未编译工程冒充 APK/EXE。

## Android 加固

所有正式 APK 默认执行 release 安全检查。用户明确说“加固 APK”时，不再询问加固等级，直接执行当前环境、构建链和项目兼容范围内能做到的最好加固，允许使用可信第三方工具。

至少执行：

1. 生成加固前 release APK，记录 SHA-256、大小、包名和版本。
2. 关闭调试和测试配置，移除敏感日志、测试接口、演示账号与秘密字符串。
3. 执行代码/资源压缩、优化和混淆，补齐反射、JNI、序列化、路由、模型与插件保留规则。
4. 收敛导出组件，检查 WebView、深链、备份、剪贴板、本地存储和 HTTP 放行范围。
5. 在兼容前提下加入防调试、防篡改、完整性/签名校验、关键逻辑最小暴露和风险环境检测。
6. 当前环境有可信且兼容的第三方加固工具时实际执行；否则交付最高可实现的内置加固并准确说明。
7. 记录加固后 APK 的 SHA-256、大小、版本、加固方式和兼容测试结果。

## 签名交付

最终正式签名由用户完成：

- 默认交付 `*-hardened-unsigned.apk`。
- 提供 `zipalign`、`apksigner` 的建议顺序、示例命令和验证方法。
- 不索取、不保存、不上传用户的正式签名私钥和密码。
- 如安装回归需要签名，可额外生成明确标记的临时 `test-signed` 副本；测试副本不得作为正式发布包。
- 第三方工具要求已签名输入时，优先使用用户主动提供的测试证书；没有时选择支持未签名输入的方案，或明确记录该步骤受限。

不得把改文件名、改哈希、压缩 ZIP、简单字符串拆分或普通 R8 混淆单独宣称为完整第三方壳加固。

## 网页发布检查

- 新版固定 PHP8.2 + MySQL8.0；旧版固定 PHP7.4 + MySQL5.6/5.7，并检查安卓手机 KSWEB 兼容。
- 后台自用版固定 `/adminsc + admincs/asd.cc`；经典版固定 `/admin + admin/123456`。
- 不强制首次登录改密；登录页不得展示凭据，数据库只保存密码哈希。
- 默认兼容 HTTP 与 HTTPS，不强制证书；使用 HTTP 时检查 Cookie、回调、资源和 API 不因 Secure 或硬编码 HTTPS 失效。

## 云控发布检查

只有功能确实需要云控时才检查并接入用户提供的云控地址与资料。不得为普通本地软件强行增加云控，也不得把 App Secret、管理员密码、数据库密码或长期万能令牌打包进客户端。

## 发布前检查

1. 语法、依赖、路径和配置模板。
2. 干净环境构建及产物存在性。
3. APK 加固、结构、对齐、临时测试签名、安装/升级；EXE 启动；Web 安装/部署。
4. 数据库迁移与旧数据。
5. 登录、权限、上传下载、离线、重试和异常恢复。
6. 客户端秘密、后台凭据、安全、隐私和日志泄露。
7. HTTP/HTTPS、本地/KSWEB、云控可选接入和地址异常。
8. UI、安全区、图标、响应式和正式文案。
9. 功能矩阵与 FEATURES 对照，确认旧功能未丢失。

## 最终报告

列出版本号、产物、检查范围、网页环境、后台模式、HTTP/HTTPS状态、云控状态、数据库变化、APK加固方式、正式签名待用户完成状态、测试结果、未验证项、已知限制和升级步骤。只有在实际生成并检查产物后才能提供“已完成”结论。
