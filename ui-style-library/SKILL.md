# 多风格 UI/UX 开发 Skill

## 1. 何时读取

涉及网站、App、PC客户端、插件、后台、页面、组件、图标、布局、配色、字体、动效、响应式、无障碍或视觉改版时，开发前必须读取本文件。纯后端、数据库、命令行脚本且不改变用户界面时可跳过。

## 2. 强制工作流

1. 先分析产品类型、目标用户、使用场景、内容密度、设备、品牌气质、性能与无障碍要求。
2. 从下列风格中选择一个主风格；必要时只允许再选一个辅助风格或一种微交互语言。不得把多种风格无规则混合。
3. 说明选择理由、适用页面、禁用页面和风险。暖黄、米白、大圆角、轻阴影可以使用，但不得默认或优先使用；必须由产品定位和同类优秀产品研究决定。
4. 开发前建立设计令牌：颜色、字体、字号、行高、间距、圆角、边框、阴影、层级、图标、动效时长、断点和状态色。组件中禁止散落无规则硬编码。
5. 先完成核心页面与完整状态：默认、按下、悬停、焦点、禁用、加载、空数据、错误、成功、离线、权限不足。
6. 移动端必须处理状态栏、刘海、挖孔、导航栏和手势安全区。背景可以延伸到系统区域，但标题、按钮、列表、输入框等正文必须从安全区内开始，不得与时间、电量、信号或手势条重叠。
7. 交付前检查响应式、键盘导航、屏幕阅读、对比度、触控尺寸、深色模式、减少动效、低性能设备和横竖屏。

## 3. 全局质量底线

- 正文默认不小于 16px；重要触控目标建议不小于 44×44px，目标之间留有误触间距。
- 文本与背景对比度至少满足 WCAG AA；不得仅靠颜色表达成功、失败或选中状态。
- 图标使用统一风格 SVG 或原生矢量资源，不使用表情符号冒充功能图标。
- App 图标必须简洁、缩小可辨、前景与背景分离并位于自适应图标安全区；避免截图式、剪贴画式、细碎元素、过多文字和通用 AI 机器人造型。
- 动效必须说明状态或空间关系；普通反馈建议 100–300ms。所有持续动画、视差、弹性和强动效都要提供减少动效方案。
- 玻璃、液态、空间、拟物和极光效果不得损害文字对比、滚动性能、表单可用性和低端机体验。
- 数据表格、长表单、财务、医疗、后台管理等高密度或高风险场景，优先清晰、稳定和可访问，不以视觉特效为首要目标。

# 4. 精选风格目录

## 4.1 极简主义与瑞士风格（Minimalism & Swiss Style）

**核心特征**：严格网格、充足留白、强信息层级、几何结构、无衬线字体、单一强调色、装饰最少。

**适合**：企业工具、SaaS、文档、专业后台、编辑器、效率应用、内容管理。

**慎用**：儿童、娱乐、强情绪品牌、需要丰富叙事或艺术表达的产品。

**建议令牌**：8px 基础间距；12列网格；圆角 0–8px；阴影不用或极轻；黑白灰为基础，最多一个品牌强调色。

**实现重点**：标题层级必须明确；内容宽度受控；边框、间距和字号承担层级，不依赖大量卡片和阴影。

## 4.2 新拟态（Neumorphism）

**核心特征**：同色系背景、凸起/凹陷表面、双向柔和阴影、圆润控件、轻微实体感。

**适合**：冥想、健康、音乐控制、少量交互的展示型工具和单功能面板。

**慎用**：复杂后台、长表单、数据密集、无障碍要求高、户外高亮环境。

**建议令牌**：圆角 12–16px；2层柔和阴影；同一色相明暗变化；按下时使用内阴影和轻微缩放。

**实现重点**：边界必须清楚，文本和控件对比度要补强；不能让输入框、按钮、卡片全都看不出层级。

## 4.3 玻璃拟态（Glassmorphism）

**核心特征**：半透明面板、背景模糊、轻边框、分层和光感。

**适合**：弹窗、导航、媒体控制、品牌首页、轻量仪表盘和高级感展示。

**慎用**：低性能设备、文字密集、复杂表单、低对比背景、关键业务操作。

**建议令牌**：透明度 12%–28%；模糊 10–20px；1px 半透明边框；层级不超过3层。

**实现重点**：每个玻璃面板后方必须有可控背景；无 `backdrop-filter` 时提供不透明降级；正文对比度必须单独验证。

## 4.4 黏土拟态（Claymorphism）

**核心特征**：厚实、柔软、玩具感、膨胀体积、较大圆角、内外双阴影、轻弹性反馈。

**适合**：教育、儿童、休闲游戏、创意工具、轻松型新手引导。

**慎用**：金融、医疗、法律、严肃企业后台和高密度数据界面。

**建议令牌**：圆角 16–24px；较厚轮廓；内外阴影；柔和但有对比的配色；弹性动效 180–350ms。

**实现重点**：可爱不等于幼稚；控制组件数量，避免每个区域都做成鼓包卡片。

## 4.5 极光界面（Aurora UI）

**核心特征**：流动网格渐变、极光色带、光晕、氛围背景和缓慢色彩变化。

**适合**：品牌首屏、音乐、创意平台、生活方式、活动页、Premium 功能展示。

**慎用**：长文、后台表格、关键表单、需要极高对比度的业务页面。

**建议令牌**：2–4个协调色；背景动画 8–12秒；内容区使用稳定纯色或高对比面板；减少动效时静态化。

**实现重点**：极光主要作为氛围层，不能让所有按钮、卡片和文字同时渐变；避免俗套紫色渐变成为默认方案。

## 4.6 扁平化设计（Flat Design）

**核心特征**：二维、纯色、简洁图形、清晰排版、少阴影或无阴影、反馈直接。

**适合**：移动应用、跨端工具、SaaS、企业系统、启动速度优先的产品。

**慎用**：强调奢华材质、沉浸式展示和真实物理隐喻的产品。

**建议令牌**：4–6个以内的纯色；圆角 0–8px；1–2px 边框；150–200ms 状态过渡。

**实现重点**：不要因为“扁平”而丢失可点击性；按钮、输入框、标签和信息层级必须有明确状态。

## 4.7 拟物化设计（Skeuomorphism）

**核心特征**：真实材质、现实隐喻、纹理、复杂光影、立体按压和物理细节。

**适合**：音乐器材、模拟仪表、游戏、教育演示、收藏品和高端品牌体验。

**慎用**：通用企业后台、低性能设备、长表单、无障碍优先和大量数据页面。

**建议令牌**：材质纹理必须统一；阴影不超过必要层级；动效 250–500ms；提供简化模式。

**实现重点**：拟物服务于理解和触感，不是堆叠木纹、皮革和高光。避免影响可读性和加载性能。

## 4.8 液态玻璃（Liquid Glass）

**核心特征**：流体玻璃、形态变换、动态模糊、虹彩、折射感和顺滑过渡。

**适合**：品牌体验、高端电商、创意工具、媒体封面、少量关键交互。

**慎用**：低端设备、数据后台、复杂表单、无障碍关键页面和大面积长列表。

**建议令牌**：变形 400–600ms；模糊约 12–18px；彩色折射只用于强调区域；限制同时动画元素数量。

**实现重点**：必须提供静态/不透明降级和减少动效版本；不要在滚动列表中大量实时模糊和变形。

## 4.9 微交互（Micro-interactions）

**定位**：它更适合作为所有主风格的交互增强层，而不是独立视觉皮肤。

**核心特征**：按下、切换、加载、成功、错误、拖动、滑动、收藏、复制等细小反馈。

**适合**：所有需要提升完成感和可理解性的产品，尤其移动端与生产力工具。

**建议令牌**：按下 60–120ms；状态切换 120–220ms；页面转场 180–300ms；触觉反馈仅用于关键动作。

**实现重点**：反馈要即时、可取消、与状态一致；不要为装饰而动画；错误和成功必须同时有文字/图标反馈。

## 4.10 柔和 UI 进化（Soft UI Evolution）

**核心特征**：保留柔和表面和轻深度，但提高对比度、边界、焦点状态和现代可访问性。

**适合**：现代企业应用、健康、SaaS、效率工具和希望柔和但不模糊的界面。

**慎用**：极致硬朗品牌、极高密度终端、对性能极端敏感的旧设备。

**建议令牌**：圆角 8–12px；轻柔单层或双层阴影；对比度至少 AA；动效 180–300ms；焦点环清晰。

**实现重点**：它不是传统新拟态的复制版；边界、文本和状态必须比传统新拟态更清楚。

## 4.11 便当盒网格（Bento Box Grid）

**核心特征**：不对称模块、不同跨度卡片、强视觉层级、产品特性展示和负空间。

**适合**：产品首页、功能介绍、作品集、轻量仪表盘、营销总结页。

**慎用**：长表单、密集表格、实时监控和连续长文。

**建议令牌**：桌面 4列、平板 2列、手机 1列；间距 16–24px；卡片跨度 1×1、2×1、2×2；圆角按品牌决定，不强制大圆角。

**实现重点**：先按信息重要性分配面积，再排网格；手机端必须重排，禁止缩小桌面便当盒硬塞进窄屏。

## 4.12 Y2K 美学（Y2K Aesthetic）

**核心特征**：千禧年未来主义、金属/铬、荧光、亮面按钮、泡泡形状、闪光与怀旧科技感。

**适合**：时尚、音乐、娱乐、年轻品牌、活动营销和视觉专题。

**慎用**：企业管理、医疗、金融、政府和面向老年用户的核心工具。

**建议令牌**：高饱和色控制在2–4种；金属效果集中于标题或关键控件；装饰图形不遮挡信息。

**实现重点**：保留现代可用性；不要复刻早期网页的混乱排版、低对比文字和自动播放干扰。

## 4.13 AI 原生界面（AI-Native UI）

**核心特征**：对话、流式输出、上下文卡片、生成状态、工具调用、可编辑结果、来源与撤销机制。

**适合**：聊天助手、写作、搜索、智能代理、语音助手、生成式工具和 Copilot。

**慎用**：把所有传统业务都强行改成聊天框；数据密集任务仍需结构化视图。

**建议令牌**：输入区固定但避开手势区；流式状态、停止生成、重试、复制、编辑、引用、历史和错误恢复完整；强调色不默认使用“AI紫”。

**实现重点**：AI输出必须可追溯、可中止、可修改、可恢复；长任务显示阶段进度；聊天与表单/工作台可并存。

## 4.14 便当网格（Bento Grids）

**核心特征**：更通用的内容优先模块化网格，卡片尺寸可变，强调清晰组织和响应式重排。

**适合**：个人主页、图库、摘要页、仪表盘、功能导航和内容聚合。

**与 Bento Box Grid 的区别**：Bento Box Grid 更偏强视觉营销和特性展示；Bento Grids 更偏日常信息组织与可复用组件体系。

**建议令牌**：使用 `auto-fit/minmax` 或原生自适应网格；卡片内容决定高度；禁止固定高度导致截断。

**实现重点**：卡片数量多时仍需明确分组和导航，不能把所有功能都做成同权重方块。

## 4.15 空间界面（Spatial UI / VisionOS）

**核心特征**：浮动窗口、深度层、半透明材质、焦点放大、视线/手势反馈和空间关系。

**适合**：VR/AR、沉浸媒体、3D产品展示、未来感控制台，以及少量借鉴空间层级的普通应用。

**慎用**：长文档、复杂表单、低性能设备、要求极高文字对比的页面。

**建议令牌**：玻璃层不超过必要数量；窗口圆角、深度和焦点缩放统一；普通手机/网页提供二维降级。

**实现重点**：普通 App 只能借鉴层级和焦点语言，不得假装具备真实空间交互；不能为“未来感”牺牲导航和可读性。

## 4.16 触感数字与可变形界面（Tactile Digital / Deformable UI）

**核心特征**：果冻、弹性、挤压、回弹、材质变化、按压深度和触觉联想。

**适合**：移动消费应用、娱乐、游戏、创意工具、互动演示和关键主按钮。

**慎用**：企业后台、财务数据、医疗、专业工具和运动敏感用户场景。

**建议令牌**：按下缩放约 0.95–0.98；回弹 250–450ms；弹簧参数全局统一；减少动效时改为颜色/阴影反馈。

**实现重点**：只用于少量高价值控件；列表、表格和输入区不要持续变形；触觉反馈不能替代明确状态。

# 5. 风格选择速查

- 企业后台、效率、文档：极简瑞士、Flat、Soft UI Evolution。
- 健康、冥想、轻控制：Soft UI Evolution；少量 Neumorphism。
- 教育、儿童、休闲：Claymorphism；可配微交互。
- AI写作、搜索、Agent：AI-Native UI 为交互框架，视觉可搭配极简瑞士、Soft UI Evolution 或 Bento。
- 品牌首页、音乐、创意：Aurora、Glassmorphism、Liquid Glass，必须控制范围和性能。
- 产品功能展示：Bento Box Grid；日常模块聚合：Bento Grids。
- 时尚、音乐、年轻营销：Y2K；保持现代信息架构。
- 模拟器、音乐器材、收藏体验：Skeuomorphism。
- VR/AR或未来空间体验：Spatial UI。
- 娱乐型移动主按钮与互动演示：Tactile Digital。

# 6. 组合规则

推荐组合：

- 极简瑞士 + 微交互：专业、克制、易维护。
- Soft UI Evolution + 微交互：柔和但可访问。
- AI-Native + 极简瑞士：适合生产力与写作工具。
- AI-Native + Bento Grids：适合多助手、多任务和资产工作台。
- Bento Box Grid + Glassmorphism：只在营销首页局部使用。
- Flat + 微交互：适合轻量跨端工具。
- Claymorphism + Tactile Digital：仅限轻松、娱乐或儿童场景。

禁止组合：

- 新拟态、玻璃、液态玻璃、拟物、黏土同时混用。
- 数据后台大面积使用 Aurora、Y2K、Liquid Glass 或 Spatial UI。
- 只因为产品带 AI 就默认紫色渐变、机器人图标或悬浮光球。
- 每个区域都使用大圆角卡片，导致层级单一、页面像模板拼装。

# 7. 开发输出要求

开始编码前输出并落盘：

1. 产品与用户分析。
2. 主风格、辅助风格及选择理由。
3. 设计令牌表。
4. 核心组件规范。
5. 页面结构与完整状态清单。
6. 移动端安全区、响应式、无障碍和性能方案。

项目内建议保存：

- `design-system/MASTER.md`：全局设计系统唯一来源。
- `design-system/pages/<page>.md`：页面级差异，仅覆盖必要项。
- `assets/icons/`：统一矢量图标。
- `docs/UI_REVIEW.md`：交付前UI检查结果。

已有 `design-system/MASTER.md` 时必须先读取并增量更新，不得静默覆盖用户既有决策。

# 8. 交付前检查

- 是否真正匹配产品，而非默认暖黄、米白或渐变紫。
- 是否与同类成熟大厂产品的质量、密度和交互习惯相符。
- 是否存在正文顶到状态栏、底部按钮压住手势条、横向溢出或固定像素适配单一机型。
- 是否所有功能都有加载、空、错误、禁用、成功、离线和恢复状态。
- 图标是否统一且缩小可辨；App自适应图标是否在安全区内。
- 深色模式、对比度、焦点、键盘、屏幕阅读和减少动效是否可用。
- 玻璃、模糊、渐变、3D和持续动画是否影响低端设备性能。
- 是否存在明显AI模板感、无意义装饰、过度卡片化或不一致圆角。
